# Security and privacy

SwiftClip stores clipboard history locally and unencrypted. It does not send clipboard data to a server. Marked concealed/transient/autogenerated content is ignored, but unmarked secrets can still be saved. Use Pause and Ignore Apps for sensitive workflows.

## Reporting a vulnerability

If available, use **GitHub → Security → Advisories → Report a vulnerability** for a private report. If that channel is unavailable, open an issue containing only a request for a private contact method—no exploit details, clipboard data or credentials. Do not post sensitive reports publicly.

Include the affected version, macOS version, a minimal reproduction using synthetic data and the expected/actual behavior. Never attach your history database, payload directory, unredacted diagnostics, private keys or access tokens.

There is no guaranteed response SLA. This is a personal open-source project, not a managed security service.

## Distribution model

Current releases are ad-hoc signed and not notarized. Do not mistake this for verified Developer ID distribution. Verify the release checksum and review the source/workflow before granting Accessibility. Do not disable Gatekeeper globally.

Build/release Actions are pinned to commit SHAs. Pull-request checks have read-only permissions. Only the release publishing job can write release assets. No production signing credentials are required for the current pipeline. A successful CI run does not prove every input field is safe or that every synthetic paste was delivered.
